## `harness.c`

```c
/* harness.c - a tiny interactive command loop.
 * Reads a line at a time from standard input and reacts to it.
 * Only the C standard library is used. */

#include <stdio.h>   /* printf, fgets, fputs, stdin, stdout */
#include <string.h>  /* strcmp, strcspn, strstr */

/* Longest line we are willing to read, including the '\0' terminator. */
#define MAX_LINE 256

int main(void)
{
    char line[MAX_LINE]; /* storage for the line the user typed */

    /* Loop forever; the only way out is the "exit" command or end of input. */
    while (1) {
        /* Show the prompt. printf does not add a newline here, so the
         * cursor stays on the same line as the "> ". */
        printf("> ");

        /* stdout is often line-buffered (or fully buffered when piped), so
         * force the prompt out to the terminal before we block on input. */
        fflush(stdout);

        /* Read at most MAX_LINE-1 characters into line, stopping at newline.
         * fgets returns NULL on end-of-file or a read error, which happens
         * when input comes from a pipe that has run dry or the user presses
         * Ctrl+D / Ctrl+Z. Leave the loop cleanly in that case. */
        if (fgets(line, sizeof line, stdin) == NULL) {
            printf("\n"); /* keep the shell prompt on a fresh line */
            break;
        }

        /* fgets keeps the trailing newline. strcspn returns the index of the
         * first '\n' (or of the '\0' if there is none), so writing '\0' there
         * trims the newline without touching anything else. */
        line[strcspn(line, "\n")] = '\0';

        /* strcmp returns 0 only when the two strings match exactly, so this
         * matches "exit" and not "exit now" or "Exit". */
        if (strcmp(line, "exit") == 0) {
            printf("Goodbye!\n");
            break; /* leave the while loop and fall through to return 0 */
        }

        /* strstr returns a pointer to the first occurrence of "hello"
         * anywhere in the line, or NULL if it is not present. */
        if (strstr(line, "hello") != NULL) {
            printf("Hello there! Nice to meet you.\n");
            continue; /* handled, so skip the echo below */
        }

        /* Anything else: repeat the input back exactly as it was typed. */
        printf("%s\n", line);
    }

    /* Returning 0 from main exits the program with a success status. */
    return 0;
}
```

## `test.sh`

```bash
#!/usr/bin/env bash
# test.sh - compile harness.c and feed it scripted input, no typing required.

set -e  # stop immediately if the compile or the program fails

SRC="harness.c"
BIN="./harness"

echo "== Compiling $SRC =="
cc -Wall -Wextra -o "$BIN" "$SRC"
echo "Compiled to $BIN"
echo

echo "== Running with scripted input =="
# Each printf line becomes one line of stdin for the program:
#   1. "hello world" -> should trigger the hardcoded greeting
#   2. "this is a test string" -> should be echoed back verbatim
#   3. "exit" -> should print the goodbye message and end the loop
OUTPUT=$(printf 'hello world\nthis is a test string\nexit\n' | "$BIN")

echo "$OUTPUT"
echo

echo "== Checking output =="
FAILED=0

# Confirm the greeting branch ran.
if echo "$OUTPUT" | grep -q "Hello there!"; then
    echo "PASS: 'hello world' produced the greeting"
else
    echo "FAIL: 'hello world' did not produce the greeting"
    FAILED=1
fi

# Confirm the echo branch repeated our test string.
if echo "$OUTPUT" | grep -q "this is a test string"; then
    echo "PASS: test string was echoed back"
else
    echo "FAIL: test string was not echoed back"
    FAILED=1
fi

# Confirm the exit branch ran.
if echo "$OUTPUT" | grep -q "Goodbye!"; then
    echo "PASS: 'exit' terminated the program"
else
    echo "FAIL: 'exit' did not terminate the program"
    FAILED=1
fi

echo
if [ "$FAILED" -eq 0 ]; then
    echo "All tests passed."
else
    echo "Some tests failed."
fi

exit "$FAILED"
```

## What was added

Typing `calc` followed by an expression routes the line to a recursive-descent parser: one function per precedence level, where addition calls multiplication, which is what makes `2 + 3 * 4` yield 14 without any explicit precedence table. It handles `+ - * / %`, parentheses, decimals, and unary signs.

The dispatch is a table rather than an `if` chain, so a second tool is one function plus one row:

```186:196:harness.c
typedef struct {
    const char *name;
    void (*run)(const char *args);
} Tool;

static const Tool tools[] = {
    { "calc", tool_calc }
};
```

Three decisions worth surfacing, since each is a place the obvious approach would have bitten:

Remainder is computed by hand as `left - right * (double)(long long)(left / right)` instead of calling `fmod`, because `fmod` can require linking `-lm` on some systems and you specifically need bare `gcc harness.c -o harness` to work. The tradeoff is that a quotient exceeding `long long` range would misbehave, which no calculator input will reach.

The tool name must be followed by a space or end-of-line, otherwise `calculate my taxes` would dispatch to `calc` and then fail to parse.

Division by zero reports separately from a malformed expression. Without that, the two error tests in `test.sh` would each pass whenever *either* code path worked, quietly hiding a break in the other.

The test script now covers precedence, parentheses, decimal results, remainder, divide-by-zero, and a malformed expression — nine checks total. If any come back `FAIL`, or gcc reports anything, send me the output.
